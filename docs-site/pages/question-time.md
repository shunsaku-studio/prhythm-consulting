# 先輩質問タイム

理解の確認は、ファインマン・テクニックを下敷きにした「先輩質問タイム」で行う。ジュニアが成果物を閉じて自分の言葉で説明し、先輩が質問し、理解度を記録する。平易な言葉で説明できないところが、理解できていないところだ。

この仕組みをスキルの外に置くのは、飛ばされないようにするためだ。スキルの中の確認手順は、忙しいときに真っ先に省かれる。人と人の約束は、それより省かれにくい。さらに、**質問タイムを通っていない成果物は、マネージャーのレビューに出さない**。質問タイムは任意の研修ではなく、ワークフローの通過条件だ。

## 運用

| 項目 | 決め方 |
|------|--------|
| いつ | 主要ゲートの前の 3 回。① 目標の解釈を合意する前、② 追う打ち手を選ぶ前、③ 最終メッセージを確定する前 |
| 誰が | 質問役は 1〜3 年上の先輩。マネージャーのレビューとは分け、評価の場にしない |
| 時間 | 1 回 15〜20 分。1 案件（約 2 週間）で合計 1 時間程度 |
| 記録 | 先輩が案件フォルダの `reviews/question-time.md` に、点数と詰まった問いを 2 分で書く |

## 1 回の進め方

1. ジュニアが成果物を閉じ、結論とその根拠を 3 分で説明する。相手はクライアントの新任役員だと想定し、専門用語に頼らない
2. 先輩が、下の「定番の問い」から 5〜6 問を投げる（10 分）
3. 先輩が、詰まった問いを記録する。ジュニアは元の資料に戻って埋める
4. 先輩が理解度を採点し、上に出してよいかを判定する。届かなければ、詰まった問いだけを 5 分で再確認する

## 定番の問いと採点

| 観点 | 定番の問い |
|------|-----------|
| 結論 | 一言で言うと何が言えるのか。だから何をすべきか |
| 出所 | この数字はどこから来たのか（ID でたどる） |
| 前提 | どの前提が変わると、結論が変わるか |
| 別解 | ほかにどんな説明や打ち手がありえたか。なぜ捨てたか |
| 弱点 | この成果物で一番弱いのはどこか。社長に突っ込まれるならどこか |

各観点を 0〜2 点で採点する。

| 点 | 基準 |
|:--:|------|
| 0 | 答えられない |
| 1 | 資料を見れば答えられる |
| 2 | 資料なしで自分の言葉で答えられる |

**上に出してよい基準**は、10 点満点で 7 点以上、かつ「出所」と「前提」がともに 1 点以上。この基準は仮置きで、パイロットで調整する。

## 記録の型

```markdown
## 質問タイム② 追う打ち手を選ぶ前（2026-11-09）
- ジュニア: 佐藤 / 先輩: 田中 / 対象: 05-initiatives.md, 06-capital.md
- 点数: 結論 2 / 出所 1 / 前提 1 / 別解 2 / 弱点 1 = 7 → 通過
- 詰まった問い:
  - 「I-004 の獲得率 8% はどこから？」→ 推定の計算式を説明できず。facts.csv をたどって再確認済み
  - 「借入余力の前提の D/E 0.5 倍は誰が決めた？」→ 開示資料 p.4 と答えられた
```

## 守ること

- **点数は人事評価に使わない。** 評価に使うと、ジュニアは取り繕う準備に時間を使い、先輩の採点は甘くなる。点数は、本人と育成担当が伸びを見るためだけに使う
- **記録は型の改善に回す。** 詰まった問いが溜まると、「どのスキルの成果物で、どの観点で詰まりやすいか」が見えてくる。これを各スキルの `pitfalls.md` と、定番の問いの見直しに反映する
- **スキル側で用意するのは、先輩向けの問いの種だけ。** 各スキルの `references/questions.md` に、そのスキルの成果物について先輩が聞くとよい問いを 3〜5 個置く。先輩が任意で読むもので、ジュニアに手順を強制するものではない
