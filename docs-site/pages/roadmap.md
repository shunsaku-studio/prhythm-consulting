# 開発の進め方とロードマップ

## 仮想お題からスキルを逆算する

スキルは一覧から作らず、仮想の主要お題から逆算して作る。スキル同士のつなぎ目、つまり一つの成果物が本当に次のスキルの入力になるかは、お題を最後まで通して初めて分かる。また、通しで使われないスキルを作らずに済む。

1. 仮想の主要お題を四つ定める。業種とビジネスモデル、依頼文、制約をセットにする
2. お題ごとに、ビジネスケースを組むワークフローを描く。各ステップの問い、使うスキル、ゲート、質問タイムの位置を決める
3. ワークフローに出てくるスキルを洗い出し、お題をまたいで何回使われるかを数える
4. 使われる回数が多く、既存の道具で代替できないものから作る
5. 1 本目のお題を、作ったスキルで最後まで通す。通すたびにスキルを直してから、次のお題に進む

お題は、次の四つの条件で選んだ。コンサルへの依頼として頻度が高いこと、資本の論点を含むこと、公開情報だけで外から仮説が立つこと、互いに違うスキルを要求すること。実在企業は使わない。特定企業の評価を公開せずに済み、論点を設計しやすいからだ。

## いまの状態（プロトタイプ）

| フェーズ | 中身 | 状態 |
|---------|------|------|
| Phase 0 | 台帳と ID の決まり、お題A の検証用データ、スキルの雛形、number-audit | 済 |
| Phase 1 | 三つ以上のお題で使うスキルを正式に作り、お題A を最後まで通す。お題A だけで使うものは仮の型 | 済 |
| Phase 2 | お題B（資本効率）と D（M&A）を通す。portfolio-matrix、ma-screening を作り、企業評価は既存の道具に連携する | 未着手 |
| Phase 1 追加 | 定番フレームワーク（PEST、ファイブフォース、3C、バリューチェーン、SWOT）を、ベストプラクティスを調べたうえで正式なスキルにする。道具の存在を知ってもらうため | 済 |
| Phase 3 | お題C（新規参入）を通す。segmentation、customer-kbf、インタビューの型を足す | 未着手 |

お題を一つ通すごとにゲートを置き、通れなければ次のフェーズに進まない。

## プロトタイプで扱っていないもの

- インサイドアウトのモード（社内データでの差分更新）と、案件の進行を管理する case-conductor
- PowerPoint と Excel の書き出しの標準化。Excel は business-case-model の数式入りモデルだけを出す
- 有料データ（TDnet API、業界レポート、イベントトランスクリプト）
- 実在の中計を使ったバックテスト（先読みを避けられる題材が当面少ない）
