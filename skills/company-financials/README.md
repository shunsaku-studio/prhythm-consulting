# company-financials

## 概要

社名と証券コードを渡すと、有価証券報告書（と決算短信）から PL、BS、CF とセグメント別の数字を年度ごとに取り、出典付きの縦持ち CSV `facts/financials.csv` にまとめる。同時に、セグメントの組み替え、会計基準の変更、買収のあった年、前年比の大きな動き、セグメント合計と連結の食い違いを一覧にする。数字の読み解きはしない。読み解きは financial-analysis が、成長の内訳は growth-decomposition が受け持つ。

## 利用メリット

- すべての値に資料名とページが付き、台帳 `facts/facts.csv` の ID でたどれる。
- 時系列のどこが比べられないかが先に分かる。組み替えをまたいだ前年比で誤った結論を出さずに済む。
- 後の財務系スキルが同じ CSV を読むので、数字を写し直す手間と写し間違いがなくなる。
- 新しい有報が出たら差分だけ足せる。既存の ID は変わらない。

## 利用シーン

- 提案前に、対象企業の 10 年分の推移を並べたいとき
- セグメント別の伸びと利益率の推移を見たいとき
- 中計の実績値を、有報の数字で裏取りしたいとき

依頼の例: 「この会社の数字、10 年分並べといて」「セグメント別の推移を出して」「EDINET から財務データを落として」

## 使い方

**いつ使うか:** お題A の 3 段目（現状と成長の内訳）の最初に使う。出力は financial-analysis、growth-decomposition、capital-capacity、business-case-model が読む。target-math は、この出力ができたら再実行して自社実績の行を埋める。

1. 社名、証券コード、取りたい年度を渡す。EDINET の API キーがあれば環境変数 `EDINET_API_KEY` に入れる。
2. キーがあれば、スキルが `fetch_edinet.py` で書類を探して CSV を取る。キーがない年度や古い年度は、有報の PDF から縦持ち CSV を手で作る。
3. スキルが `normalize.py` で `facts/financials.csv` を作り、台帳に登録する。
4. スキルが不連続の一覧を出す。各行の原因を有報の注記で確かめ、前提と未確認事項に書く。
5. 組み替え後の比較情報があれば足して再実行し、同じ定義での前年比を出す。

## 人が決めること

このスキルには止まって決めてもらう場面はない（単独度 ◎）。ただし次は人が確かめる。

- 不連続の原因の読み取り。スクリプトは「前年比が大きい」「注記に組み替えの語がある」までしか言えない。
- 組み替え前の年度を、後のスキルでどう扱うか（組み替え後の値で読み替えるか、その年をまたぐ比較をやめるか）。

## よく外す点

- セグメントの組み替えや会計基準の変更をまたいで、そのまま前年比や年率を出す。
- 子会社の取得がある年の売上の伸びを、オーガニックの伸びとして扱う。
- 日本基準の「営業利益」と IFRS の「営業利益」「事業利益」を同じ項目として並べる。
- 出典のページを残さずに数字だけ写す。

詳しくは [references/pitfalls.md](references/pitfalls.md)。

## 具体例

FY2016〜FY2025 の 192 行を `facts/financials.csv` にした。不連続として、FY2019 の子会社株式の取得 95 億円 [F-125]（買収した小規模な精密部品会社の売上寄与 60 億円 [F-247]）と、FY2021 のセンサー事業の移管を拾った。組み替え後の前年比は産業機械部品 +17.5% [F-245]、電子部品 -3.7% [F-246]。FY2025 の売上高は target-math が 1 日目に登録した [F-001] を使い回し、同じ事実を二重に登録していない。
