# method — 手順と、なぜその順か

## 全体の順番

1. 書類を集める
2. 縦持ち CSV に揃え、台帳に登録する
3. 不連続を洗い出し、原因を注記で確かめる
4. 組み替え後の値を足す
5. 後のスキルに渡す

集めてから揃えるまでをスクリプトにするのは、写し間違いを減らすためと、すべての値に出典のページを残すためである。不連続を最後でなく揃えた直後に見るのは、後のスキルが年率や比率を出す前に「どこが比べられないか」を決めておく必要があるからである。

## 1. 書類を集める

| 入手先 | 取れるもの | 限り |
|--------|----------|------|
| EDINET API v2（無料、要 API キー） | 有報の XBRL と CSV（UTF-16、タブ区切り） | 過去書類の保持期間に限りがある（期間は EDINET の案内で要確認） |
| 有報の「経営指標等の推移」 | 主要な数字の 5 期分 | 項目が少ない。セグメントは載らない |
| 決算短信（会社の IR ページ） | 四半期と通期の速報値 | 四半期報告書は 2024 年に廃止。四半期はここから取る |
| TDnet API | 短信の一括取得 | 法人向けは有料（月 7 万円・税抜〜）。J-Quants の TDnet アドオンは個人向けで法人は使えない |

10 期を揃えるときは、最新の有報と 5 年前の有報の「経営指標等の推移」を重ねるのが早い。重なる年度で値が違えば、遡及修正か組み替えがある。

## 2. 揃える

既定の項目:

- PL: 売上高（売上収益）、営業利益、親会社株主に帰属する当期純利益
- BS: 総資産、純資産、現金及び預金、有利子負債（なければ借入金と社債）
- CF: 営業 CF、設備投資額、減価償却費、子会社株式の取得による支出、配当金の支払額
- セグメント: 売上高、セグメント利益、調整額（全社費用）

揃え方の決まり:

- 1 行に 1 つの値。年度 × 項目 × セグメント × 会計基準 で一意
- 項目名は資料の名前のまま（日本基準の「売上高」と IFRS の「売上収益」を同じ名前に書き換えない）
- 資料のページを `source` に書く。EDINET なら要素 ID を書く
- 分からない値は — のまま。前後の年から補わない

## 3. 不連続を洗い出す

スクリプトが出す種類と、人が確かめること:

| 種類 | スクリプトの判定 | 人が確かめること |
|------|---------------|----------------|
| 不連続（注記） | 注記に「組み替え」「移管」「会計基準」などの語がある | 何がどこからどこへ動いたか。いくら分か |
| 不連続（注記のある年の変動） | 注記のある年・セグメントで前年比が閾値を超えた | 変動のうち組み替えによる分 |
| 不連続（会計基準） | 同じ項目で会計基準が年によって違う | IFRS 移行の年。移行前後の差 |
| 非連続（M&A） | 子会社株式の取得による支出がある | 買収した会社と売上の規模。翌年以降の売上に入る分 |
| 要確認（前年比） | 前年比が閾値（既定 20%）を超えた | 景気、価格、為替、一過性の損益。不連続でなければそう書く |
| 要確認（合計） | セグメント合計（+ 調整額）が連結と合わない | セグメント間取引の消去、組み替え、写し間違い |
| 要確認（欠年） | 年度が飛んでいる | 決算期の変更か、取り漏れか |

注記を読まずに「スクリプトが何も言わなかったから連続」とはしない。

## 4. 組み替え後の値を足す

有報には、組み替えた年の前期の数字を新しい区分で示した比較情報が載ることがある。これを `売上高（組み替え後・参考）` のような別の項目として足すと、スクリプトが同じ定義での前年比を出す。

お題A の例: FY2021 にセンサー事業を産業機械部品から電子部品へ移した。組み替え前の数字どうしだと電子部品は前年比 +36.8% だが、組み替え後の前期の数字と比べると −3.7% になる。

## 5. 渡す

- `facts/financials.csv` を後のスキルが読む。列は CONVENTIONS §9
- `facts/financials.md` に不連続の一覧を残す。後のスキルは、ここに書かれた年をまたぐ比較で注意書きを付ける
