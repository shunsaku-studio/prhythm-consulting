# gap-bridge

## 概要

基準年の売上、市場成長率、年数、目標を渡すと、市場成長だけで伸びた場合の売上（成り行き S）と、目標との差（ギャップ G）をセグメント別と合計で返す。ギャップを打ち手のレバー（シェア獲得、新市場、M&A、価格など）に割り当てると、それぞれが市場成長に上乗せして年何 pt を求めるかを計算する。シェアのレバーが年 5pt を超えたら赤旗を立てる。

## 利用メリット

- 「5,000 億円」が、どのセグメントにいくら足りないかの話に変わる。
- シェアで埋める案の無理を、ベースレート（平均 0.8pt/年）と並べて示せる。
- 赤旗が、二本目のレーン（M&A、市場の選び直し）を検討する根拠になる。
- S と G が ID 付きで台帳に載るので、後の打ち手の見積もりやストーリーがそこから数字を引ける。

## 利用シーン

- 目標の仕様が決まり、市場の成長率の前提も確定した直後（お題A の 1 週目末）
- マネージャーに「どこにいくら足りないのか」を聞かれたとき
- シェアで埋める案が出て、その無理を確かめたいとき

依頼の例: 「成り行きだといくら？」「5000 億まで、どこにいくら足りないか出して」「シェアで 800 億って無理ある？」

## 使い方

**いつ使うか:** target-math（目標の仕様）と market-sizing（成り行きの前提）の後に入る。出力の `03-gap-bridge.md` は option-longlist、initiative-sizing、storyline が読む。

1. 基準年の売上（セグメント別）、市場成長率、目標の ID を台帳から集める。分からない値は — のまま残す。
2. スキルが `scripts/gap_bridge.py` を回し、成り行きとギャップを出す。
3. 割り当て案があれば、レバーを足して回す。シェアの赤旗と、平均 0.8pt なら何億円にとどまるかが出る。
4. スキルが `03-gap-bridge.md` を書き、台帳に S・G の行を足す。
5. スキルは止まり、人に判断を返す。

## 人が決めること

- 成り行きに使う市場成長率（market-sizing のゲートで確定したものか）
- セグメント別の目標を置くか（置かなければ、セグメント別のギャップは — のまま。合計を按分しない）
- レバーへの割り当ては仮置き。追う打ち手は後の段で決める
- 二本のレーンのどちらを前に出すか（最終メッセージのゲートで決める）

## よく外す点

- 成り行きに、自社の過去の伸びをそのまま使う（市場成長とシェアが混ざる）
- 合計のギャップをセグメントの売上比で按分する
- シェアのレバーに大きな額を載せ、年何 pt に当たるかを見ない
- 赤旗を「無理です」で終わらせ、二本目のレーンにつなげない

詳しくは [references/pitfalls.md](references/pitfalls.md)。
