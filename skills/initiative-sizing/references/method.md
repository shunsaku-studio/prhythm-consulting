# 手順と、なぜその順か

## 1. 式

**市場 × シェアの施策**

```
上乗せ売上_y = 市場規模 × (1 + 市場成長率)^(y − 基準年) × 上乗せシェア × 立ち上がり率_y
```

**買収の施策**

```
上乗せ売上_y = 買収先の売上 × (1 + 市場成長率)^(y − 連結開始年)   （連結開始年から）
```

買収は連結した年から満額で入る。そのかわり、買収額の全体を投資として置く。統合の効果（シナジー）はこの式に入れない。入れるなら別のカードにして、確度を分ける。

## 2. 立ち上がり率

開始年を 1 年目（t = 1）、満額に届く年数を R とする。

| 曲線 | 式 | 使う場面 |
|------|----|---------|
| S 字（`s`） | ロジスティック曲線を t = 0 で 0、t = R で 1 になるよう正規化 | 新規顧客の開拓、新市場。最初の数年は遅い |
| 直線（`linear`） | min(1, t / R) | 既存顧客への能力増強。受注が見えている |
| 満額（`step`） | 1 | 買収だけ。自前の施策で使うと警告が出る |

R = 4 の S 字なら、立ち上がり率は 1 年目およそ 0.15、2 年目 0.5、3 年目 0.85、4 年目 1 になる（スクリプトの出力で確かめる）。直線なら 0.25 ずつ増える。

## 3. なぜ「上乗せシェア」で入れるか

gap-bridge の成り行き（S）は、今のシェアのまま市場成長で伸びた姿である。施策の売上にシェア全体を掛けると、成り行きに入っている分を二重に数える。だから入力は「成り行きに上乗せするシェアの pt」にする。

上乗せシェアの大きさは、ベースレートと比べる。McKinsey（2017-08）では、成長企業でもシェア獲得による成長は年 0.8pt 程度で、シェア獲得だけで年 5% 超を 10 年平均で得た企業は 13% にとどまる。スクリプトは上乗せシェアが 5pt を超えると警告を出す。

## 4. なぜ値ではなく ID を入力に書くか

入力 CSV に値を直接書くと、台帳の値を差し替えたときに入力が古いまま残る。ID を書いておけば、台帳を直して回し直すだけで全体が更新される。I-xxx の台帳の行には、どの ID から計算したかが式で残る。

## 5. なぜ確度を人が決めるか

確度は、数字の正しさではなく「この前提にどれだけ賭けられるか」の判断である。顧客との関係、競合の動き、社内の実行力など、スクリプトが知らない情報で決まる。作業者が決めると、楽観的な前提に高い確度が付きやすい。スキルは — のまま渡し、人が決めたら入力に書いて回し直す。

## 6. 順番

1. 台帳に入力を登録する（出典タグと期限）
2. 入力 CSV を書く
3. 先輩と前提を合意する（△）
4. スクリプトを回す
5. 人が確度を決める
6. 回し直して、05-initiatives.md にまとめる

前提の合意を回す前に置くのは、数字を見てから前提を動かすと、目標に合わせた見積もりになりやすいからである。
