# kpi-roadmap

## 概要

KPI ツリーとモデルを渡すと、FY2026〜FY2030 の年度別の KPI 目標、施策ごとの年単位の矢羽、Go/No-Go ゲートの表が返る。ゲートには、指標・閾値・期日・データの出どころ・Go のときの行動・撤退基準を必ず書く。表はスクリプト `scripts/render_roadmap.py` が CSV から組み、`08-kpi-roadmap.md` に書く。判定基準の欠けたゲートは、スクリプトがエラーにする。閾値と撤退基準は人が決める。

## 利用メリット

- 「いつ、何を見て、続けるかやめるかを決めるのか」が一枚になる。
- ゲートの閾値が台帳の K- の値なので、モデルや目標が変わったときにずれを拾える。
- 判定基準の書き忘れを、スクリプトが機械的に見つける。
- 撤退基準を先に決めておくので、始めた施策を惰性で続けにくくなる。

## 利用シーン

- 追う打ち手が決まり、モデルと感応度が出たあと
- 「年度ごとの目標を置いて」「ゲートと撤退基準を決めたい」と言われたとき
- 経営会議の前に、判断の時期と基準を示したいとき

依頼の例: 「ロードマップ引いて」「年度ごとの KPI 目標置いて」「ゲートと撤退基準決めたい」「いつ何で判断するか整理して」「矢羽書いて」

## 使い方

**いつ使うか:** お題A では 9 段目（ロードマップ）。前は kpi-tree・business-case-model・scenario-sensitivity、後は storyline。

1. `templates/` の `kpi-targets.csv`、`arrows.csv`、`gates.csv` を `cases/<案件>/roadmap/` に写す。`08-kpi-roadmap.md` を案件フォルダに写す。
2. KPI 目標を書く。売上や ROIC の年次の値はモデル（`model/model.csv`）から取り、`source` にモデルの F- の ID を書く。施策の先行指標（受注、稼働率など）は KPI ツリーから 1〜2 個選ぶ。
3. 矢羽を書く。施策ごとにフェーズと開始・終了の年度を書く。
4. ゲートを書く。取り返しのつかない約束（大きな投資、契約、参入）の直前に置く。指標は感応度の上位から選ぶ。
5. スクリプトを回す。`--assign-ids` で、id の空いた KPI 目標に K- を振り、台帳に載せる。

   ```bash
   python3 skills/kpi-roadmap/scripts/render_roadmap.py --case cases/hokushin --assign-ids
   ```

6. 画面に出た「直すこと」を直す。「人が決めること」を持って、マネージャーと閾値と撤退基準を決める。
7. 決めたことを `decisions.md` に D- で残し、`gates.csv` の `decision_id` に書いて回し直す。

### 矢羽の書き方

| 表示 | 意味 |
|------|------|
| `【受注獲得】` | フェーズの最初の年度 |
| `━━━` | フェーズが続く |
| `━━▶` | フェーズの最後の年度 |
| `【量産立ち上げ】▶` | 1 年だけのフェーズ |
| `◆G1` | その年度にゲート G1 がある |

### ゲートの判定基準（全部そろって一つのゲート）

| 欄 | 書くこと | 例 |
|----|----------|----|
| 指標 | 何を見るか | 量産受注の年換算売上 |
| 閾値 | どこで線を引くか（台帳の K- の値） | — [K-xxx] |
| 期日 | いつ判断するか | YYYY-MM-DD |
| データの出どころ | 何で確かめるか | 受注台帳（社内。受注後に取得） |
| Go のとき | 何を実行するか | 量産ライン投資の発注 |
| 撤退基準 | 何がどうなったら、何をやめるか | 閾値に届かなければ投資を見送る |

## 人が決めること

- 各ゲートの閾値、期日、撤退基準（お題A の「ゲートと撤退基準を確定」）
- どの KPI を年度別の目標として持つか
- 撤退したときに、どの段（打ち手、資本、目標）に戻るか

スクリプトは閾値を決めない。合意していない数字で閾値を埋めず、— のまま「人が決めること」に残す。決めたことは `decisions.md` に `D-` で残す。

## よく外す点

- ゲートに判定基準が書かれていない。「FY2027 に見直し」だけでは、何を見て何を決めるのか分からない。
- 撤退基準がない。続ける条件だけを書き、やめる条件を書かない。
- 閾値がモデルや台帳とつながっていない。目標を変えても閾値が古いまま残る。
- ゲートのデータが、その時期に手に入らない（公開情報では見えない受注など）。
- 年単位の計画に、月単位の作業を詰め込む。

詳しくは [references/pitfalls.md](references/pitfalls.md)。
