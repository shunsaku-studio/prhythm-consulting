# kpi-tree（仮の型）

## 概要

売上目標（例: FY2030 に 5,000 億円）を渡すと、何が動けば達成かを示す 2 本のツリーが返る。売上のツリーは、成り行き（セグメント別、数量 × 単価）、新しい打ち手、残るギャップに分ける。ROIC のツリーは、NOPAT マージン × 投下資本回転率に分ける。各ノードに K- の ID を振り、値は台帳か `model/model.csv` から取る。分からない値は — のまま残す。出力は `07-kpi-tree.md` で、kpi-roadmap が年度別の目標とゲートの指標を選ぶときに使う。

これは仮の型である。テンプレート 1 枚とよく外す点だけを置いている。

## 利用メリット

- 「5,000 億円」が、会社が動かせるノードの組み合わせに分かれる。
- 売上を伸ばすと ROIC のどこが悪くなるか（のれん、設備）が同じページで見える。
- ノードに ID があるので、ロードマップのゲートの指標にそのまま使える。

## 利用シーン

- ギャップと打ち手が出て、モデルを組む前後
- 「何が動けば達成か整理して」と言われたとき
- kpi-roadmap の前

依頼の例: 「KPI ツリー作って」「5000 億を分解して」「何が動けば達成か整理して」「ROIC を分解して」

## 使い方

**いつ使うか:** お題A では 8 段目（KPI とモデル）。前は gap-bridge と initiative-sizing、後は kpi-roadmap。

1. `templates/07-kpi-tree.md` を `case/07-kpi-tree.md` に写す。
2. 上から順にノードを埋める。値は台帳（S-・G-・I-・F-）と `model/model.csv`（NOPAT マージン、投下資本回転率、ROIC の行）から取る。
3. 新しいノードにだけ K- を振り、台帳に載せる。分からない値は — で載せる。
4. 子を足す（掛ける）と親になるかを確かめる。合わなければ前提と未確認事項に書く。
5. どのノードを管理する KPI にするかを、レビュー役と決める。

## 人が決めること

- どのノードを管理する KPI にするか（kpi-roadmap で年度別の目標とゲートに使う）
- 合わない定義（連結とセグメントなど）をどちらにそろえるか

決めたことは `decisions.md` に `D-` で残す。

## よく外す点

- 子を足しても親にならない（セグメント合計と連結の違い）。
- 会話の中で掛け算をしてノードを埋める。
- 公開情報で分からない数量や単価を、もっともらしい推定で埋める。
- 会社が動かせない市場成長率を KPI にする。

詳しくは [references/pitfalls.md](references/pitfalls.md)。

## 具体例

- 連結売上 5,000 億円 [T-001]
  - 成り行き 2,539 億円 [S-004]（数量と単価は —、K-001〜K-006）
  - 新しい打ち手 1,268.8 億円 [F-457]
  - 残るギャップ 1,190.8 億円 [F-491]
- ROIC 7.7% [F-473] = NOPAT マージン 4.7% [K-011] × 投下資本回転率 1.63倍 [K-012]
