# pitfalls — よく外す点

## 1. エラーを消すために台帳を書き換える

悪い例: `2,100 億円 [F-012] が台帳の値 2000億円 と一致しません` を見て、台帳の F-012 を 2,100 にする。

良い例: 有報 FY2025 p.45 を開き、2,000 億円が正しいと確かめてから、成果物の 2,100 を直す。2,100 の出どころ（古い版の資料など）も確かめる。

## 2. 定義の違いを見逃す

スクリプトは値と単位だけを比べ、定義は比べない。

悪い例: 「売上 2,000 億円 [F-012]」と「売上 2,000 億円 [F-140]」。F-012 は連結、F-140 はセグメント合計（内部取引の消去前）。値が偶然同じなのでエラーが出ない。

良い例: 同じ「売上」でも、台帳の `definition` 列を並べて確かめる。とくに連結/単体、オーガニック/M&A 込み、日本基準/IFRS。

## 3. 単位のない数字を「出典あり」と思い込む

スクリプトが「出典 ID のない数字」として拾うのは、億円・%・pt・倍などの単位が付いた数字だけだ。

悪い例: 表の見出しに「（億円）」と書き、セルには素の「2,553」だけを置く。ID がなくても警告が出ない。

良い例: 表に ID の列を置くか、セルに `2,553 [S-001]` と書く。

## 4. ID のすぐ前の別の数字と比べてしまう（誤検知）

スクリプトは `[ID]` の直前 6 文字以内にある数字を、その ID の値として比べる。

悪い例: `表 3 [F-012]` — 「3」が F-012 の値と比べられ、エラーになる。

良い例: ID を数字の直後に置く。`表 3 の売上 2,000 億円 [F-012]`。年度（FY2030）、日付、ID の番号は比べない。

## 5. ID を数字から離して書く（見逃し）

悪い例: `売上は 2,100 億円で、これは有報の値である [F-012]`。数字と ID が 7 文字以上離れているので値を比べない。同じ句に ID があるので、出典なしの警告も出ない。

良い例: 数字の直後に ID。`売上は 2,000 億円 [F-012] で、有報の値である`。

## 6. 仮置きの期限を延ばし続ける

悪い例: 期限切れのたびに `replace_by` を 1 週間延ばす。台帳では誰も気づかないまま、最終デッキに仮置きが載る。

良い例: 延ばすなら `decisions.md` に D- で残す。2 回目の延長は、推定に差し替えるか `—` にするかを決める機会にする。

## 7. 施策 CSV の値は点検されない

`05-initiatives.csv` は `revenue` `investment` の列で値を持ち、`value` 列がない。スクリプトは ID の有無だけを見る。施策の値を成果物に載せるときは、施策ごとの合計を I- の ID で台帳にも登録し、Markdown では `[I-003]` で引く。

## 8. 会話の中で計算して埋める

悪い例: 「成り行きは 2,000 × 1.05^5 で約 2,553」と会話で計算し、台帳に書く。

良い例: その値を作るスキル（gap-bridge など）のスクリプトを回し、出力された行を台帳に足す。number-audit は計算しない。
