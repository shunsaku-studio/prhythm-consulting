# method — 手順と、なぜその順か

## 1. 変数ごとに幅を決める

幅は変数ごとに、根拠から決める。一律の ±10% は使わない。

| 変数 | 幅の決め方 | 形 |
|------|-----------|----|
| 市場成長（成り行き） | 業界見通しを中心に、改定の履歴で下側を決める。下方修正が続いているなら、下側を厚くとる。サブ市場の成長率（例: 内燃機関向けはマイナス、EV 向けはプラス）の構成が変わる余地も見る | 非対称 |
| 施策の実現率 | シェア獲得のベースレート（平均で年 0.8pt 前後。シェアだけで年 5% 超を続ける企業は少ない）と、自社の中計の達成の実績（前中計の売上目標の未達など） | 下側が広い |
| 立ち上がりの時期 | 自社の過去の遅れ（例: 1 年後ろ倒し）。前倒しの根拠がなければ上側は 0 年 | 片側 |
| 利益率 | 自社の過去の利益率と、定義をそろえた競合の利益率。立ち上げ期の赤字を下側に見る | 競合の範囲 |
| M&A | 過去の見送り、価格規律の発言。実行する / しないの 2 値（`init_go`） | 0 か 1 |
| 運転資本、税率 | 自社の過去の範囲 | 狭い。シナリオに入れないことが多い |

幅の値は、入力と同じ単位の値で書く（成長率 3.5% なら 3.5）。差ではない。

## 2. シナリオに入れる変数を選ぶ

上振れ・下振れは、`in_scenario=yes` の変数を同時に動かした値である。互いに関係のある変数（例: 市場成長と施策の実現率）を同時に動かすのは筋がよい。関係の薄い変数まで全部同時に最悪にすると、起こりにくい極端な値になる。どれを入れたかを表に残し、人が決める。

## 3. 1 変数ずつ動かす（トルネード）

トルネードは、1 変数だけを下振れと上振れに動かし、ほかはベースのままにした値である。振れ幅の大きい順に並べる。売上で振れ幅 0 の変数（利益率など）も、ROIC では振れ幅がある。だから売上と ROIC の 2 つで並べる。

## 4. 読み方

- 上位 2〜3 個が先に確かめる前提である。仮置きなら差し替えを急ぐ
- 上位の変数は、kpi-roadmap のゲートの指標の候補になる（例: M&A の実行、量産受注の規模）
- 下振れが目標に大きく届かないことは、計画が「無理」という判定ではない。二本目のレーン（M&A、市場の選び直し、期限や定義の相談）を開く根拠である

## 5. モデルの計算を写している理由

変数を振るには計算そのものを回し直す必要があるので、`model/model.csv` を読むだけでは足りない。`sensitivity.py` は business-case-model の `build_model.py` の計算の部分をそのまま写している。ベースの FY2030 売上が `model/model.csv` と違えば、写しが古いか、入力か確度の除外が違う。

## なぜこの順か

幅を先に人と決めてから回すのは、結果を見てから幅を変えると、見たい結論に合わせた幅になるからだ。
