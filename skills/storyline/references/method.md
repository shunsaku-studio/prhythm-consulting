# method — 手順と、なぜその順か

## 1. 先に答えを書く

最初に書くのは、各レーンの「一言で」（一文）である。ピラミッドもゴーストデッキも、その一文を支えるために組む。

なぜ: 分析の順に並べると、聞き手は最後まで何の話か分からない。経営者は最初の 1 ページで、聞き続けるかを決める。答えが先にあれば、残りのページは「なぜそう言えるか」の説明になる。

一文の型の例:

- レーン1: 「{期限}までに{目標} [T-] に届くには、{打ち手}で{ギャップ} [G-] を埋め、{投資} [C-] を手当てする必要がある。」
- レーン2: 「{ベースレート} [F-] から見て{打ち手}だけでは{ギャップ} [G-] は埋まりにくく、{M&A / 市場の選び直し / 期限の見直し}を組み合わせる道筋がある。」

## 2. 二本のレーンを同じ重さで書く

| | レーン1 | レーン2 |
|-|--------|--------|
| 立ち位置 | 中計と経営者の目標を前提にする | 目標を前提にしつつ、中計の枠の外も見る |
| 言うこと | 目標に届くには、これだけの打ち手と資本が要る | ベースレートと資本の制約から見ると、別の道筋が要る |
| 主な ID | T-、G-、I-、C-、K- | G- の赤旗、ベースレートの F-、C-、経営者の公の発言 |
| 弱くなりやすい点 | 必要量が過去の実績やベースレートから大きく外れる | 中計や経営者の発言から離れすぎ、聞き手が受け取れない |

なぜ二本か: 中計どおりの案だけでは、届かないときの手がない。外側の案だけでは、経営者の目標を否定する話に聞こえる。両方を並べ、どちらを前に出すかを人が決める。

レーン2 は「無理」と言うためのレーンではない。gap-bridge の赤旗（例: シェア獲得に年 5.9pt 前後が要るが、平均は 0.8pt）は、M&A や市場の選び直しが要るという根拠として使う。

## 3. ピラミッドを組む

- 主張 = 一言で
- 根拠は 3 つ前後（2〜5）。互いに重ならず、合わせると主張が言える組み合わせにする
- 根拠ごとに、ID 付きの事実を 1 つ以上置く。事実のない根拠は、外すか未確認事項に回す

なぜ 3 つ前後か: 1 つでは反論 1 つで崩れる。6 つ以上は聞き手が覚えられず、根拠が重なっていることが多い。

## 4. ゴーストデッキを組む

- 1 ページ目 = 一言で（そのレーンの答え）
- 次に根拠ごとのページ。根拠のページの後に、それを支えるページを置く
- 最後に、経営会議で決めることと、ゲート・撤退基準（K-）
- 各ページの見出しは主張の一文。「。」で終える。数字の直後に ID
- 6〜12 枚

見出しだけを上から読んで話が通れば、ゴーストデッキはできている。

## 5. 点検してから止まる

outline_check.py で構成を、number-audit で数字を点検してから、マネージャーに二本を見せる。数字が合っていないものを見せると、レーンの比較ではなく数字の議論になる。

## 6. レーンを決めてもらう

二本を横に並べて見せる。

| | レーン1 | レーン2 |
|-|--------|--------|
| 一言で | | |
| 聞き手に信じてもらうこと | | |
| 一番弱い事実（仮置き、—） | | |
| 経営者の公の発言との関係 | | |

決まったら `decisions.md` に D- を残し、統治メッセージを書き、前に出すレーンを先に並べ替える。後ろのレーンは消さない。「もう一つの道筋」として残す。

## なぜ計算しないか

ストーリーの段で数字を作ると、台帳にない数字がデッキに載る。ここで足りない数字に気づいたら、それはその数字を作るスキルの段に戻る合図だ。
