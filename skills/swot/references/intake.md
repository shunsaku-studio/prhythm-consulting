# 何を聞いてから始めるか（swot）

分かっていることは聞かない。案件フォルダにあるものは読んで使う。分からない値は — のまま進め、「前提と未確認事項」に書く。

## 1. この SWOT が何のためか（必須）

目的がない SWOT は作らない。目的によって、同じ事実が強みにも弱みにもなるからだ。

| 聞くこと | 例 | どこにあるか |
|---|---|---|
| 目的 | 連結売上 5,000 億円を FY2030 に（お題A）。ROE 8% を早期に（お題B）。工場向けエネルギー管理に参入する（お題C） | `00-target-spec.md` の T-xxx、`decisions.md` |
| 目的の定義 | 連結か、M&A 込みか | `00-target-spec.md`、D-xxx |
| 答える論点 | Q-xxx（例: 強みを活かせる伸びる市場はどこか） | `01-issue-tree.md` |
| ギャップ | G-xxx（どこにいくら足りないか） | `03-gap-bridge.md`（あれば） |

目的が決まっていなければ止まって聞く。「会社の SWOT を一般的に」と頼まれたら、どの判断に使うかを聞き返す。

## 2. 比べる相手（強み・弱みは相対）

- 誰と比べた強みかを決める。既定は competitor-benchmark の比較対象（3〜5 社）
- 社ごとに、比較に入れた理由を一言で書く（同じ顧客、同じ製品、目標の規模に買収で届いた例 など）
- competitor-benchmark の出力がなければ、先に回すよう勧める。回さないまま進めるなら、S と W はすべて未確認の表に入れる

## 3. 時間軸

- いつの時点の強み・弱み・機会・脅威かを決める。既定は目標の期限（例: FY2030）
- 期限の候補が二つある案件（例: FY2030 と FY2033）は、主な時間軸を一つ決め、もう一方で評価が変わる項目に印を付ける
- 機会と脅威は「今」ではなく「期限までに何が変わるか」で書く

## 4. 使える証拠

| 種類 | ファイル | 使い方 |
|---|---|---|
| 競合との差 | `facts/competitor-benchmark.md` | S・W の相対比較。※ 注記（定義の違い）をそのまま引き継ぐ |
| 収益性・効率性・安全性 | `facts/financial-analysis.md` | S・W。比率は台帳の ID で引く |
| 前中計の結果 | `facts/midterm-plan.md` | W（未達の施策）の根拠 |
| 経営者の発言 | `facts/leadership.md` | 自称の強みは未確認に置く。譲れない線は TOWS の制約に使う |
| 市場の伸び | `facts/market-sizing.md` | O・T |
| 外部環境 | pest、five-forces、three-c の出力（あれば） | O・T |

## 5. 決めておくこと

- 主な時間軸と、比べる相手
- 象限ごとの上限（既定 5 件、目安 3 件）
- 決めたことは `decisions.md` に D-xxx で残す（迷ったときだけ。既定どおりなら前提に書けばよい）
