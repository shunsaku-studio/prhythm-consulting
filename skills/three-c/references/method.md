# 手順と、なぜその順か（three-c）

3C の目的は、顧客が選ぶ理由のうえで、競合より自社が上回れる場所を見つけることである。大前研一はこれを戦略的三角関係と呼んだ。自社の強みと顧客のニーズが合うだけでは足りない。同じニーズを競合がもっとうまく満たしていれば勝てない（出典は [sources.md](sources.md)）。

## 1. 問いとセグメントを先に書く

問いが決まらないと、何を集めるかが決まらない。表の一番上に問い、市場、セグメントを書く。

セグメントは顧客の使い方で切る。同じ「精密部品」でも、EV の熱を逃がすために買う顧客と、半導体装置の精度のために買う顧客では、選ぶ基準が違う。自社が届けられる範囲（地域、販路）は別に書く。大前は、目的による分け方と、届けられる範囲による分け方を区別した。

## 2. 顧客（Customer）

セグメントごとに書く。

| 書くこと | 事実の例 | 仮説の例 |
|---------|---------|---------|
| 規模と成長 | 市場規模 [F-xxx]、成長率 [F-xxx] | — |
| 誰が買うか | 完成車メーカー、一次部品メーカー | 決めるのは設計部門か購買部門か |
| 何のために買うか | — | 航続距離を延ばすため |
| 購買基準（3〜6 個）と重み | インタビューで確かめた基準 | 「量産の立ち上げの速さが重い」 |

なぜ顧客から始めるか: 自社から始めると、自社の得意なことが基準に見えてくる。これがプロダクトアウトの罠である。

**購買基準が、以降の表の行になる。** 競合と自社は、この同じ行で見る。

アウトサイドインでは、購買基準と重みはすべて仮説である。「仮説」と書き、確かめる方法（誰に、何を聞くか）を添える。

## 3. 競合（Competitor）

- 直接の競合: competitor-benchmark の会社と ID を使う
- 代替品: 同じ目的を別の方法で満たすもの（顧客の内製、別の技術）
- 新規参入者: 隣の業界から入りうる会社

顧客の購買基準の行ごとに、各社がどう満たしているかを書く。事実なら ID、推測なら 仮説、分からなければ —。財務の比較表から読めるのは伸び方と事業構成までのことが多い。製品ごとの強さが読めないなら — のまま残す。

## 4. 自社（Company）

同じ行で、自社がどう満たしているかを書く。

- 事実: セグメント売上、利益率、シェア、設備投資、前中計の結果（ID 付き）
- 本人の言葉の強み: leadership-lens の本人発言を、短い一句と出典で
- 強みが基準のどの行に効くかを書く。どの行にも効かない強みは、この問いでは強みではない

## 5. KSF と適合・ギャップ

KSF（成功のカギ）は、次の両方を満たす基準である。

1. 顧客にとって重い
2. 勝っている会社とそうでない会社を分けている

両方を満たす基準は、セグメントごとに 1〜2 個に絞る。大前は、すべての機能で勝つ必要はなく、決定的な一つで上回ればよいと言う（選択性）。KSF は競争の構造が変われば変わる。セグメントごと、時点ごとに置き直す。

セグメントごとに次を書く。

| 項目 | 書き方 |
|------|-------|
| KSF | 購買基準の行のどれか。行にない KSF は書かない |
| 一番強い競合 | 会社名（KSF の上で） |
| 自社の位置 | 上回る / 並ぶ / 下回る / —（根拠の ID か 仮説） |
| ギャップ | 何が足りないか。数字なら ID |
| 確かめること | どのインタビュー、どの資料で |

点数を付けて順位を出さない。重みも点数も根拠がなければ作った数字になる。

## 6. 人に返す

適合とギャップの表をそろえたら止まる。どのセグメントと KSF を次の段（option-longlist）に持っていくかは人が決める。決定は decisions.md に D-xxx で残す。

## 4C・5C について

3C に協力者（Collaborators）や環境（Context）を足した型がある。起源ははっきりしない。協力者（販売代理店、提携先）が勝敗を分ける問いなら、協力者の行を足す。マクロ環境は pest、業界の構造は five-forces に渡す。
