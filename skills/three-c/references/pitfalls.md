# よく外す点（three-c）

一番多いのは、問いを決めずに三つの箇条書きを並べて終わることである。きれいに見えるが、何も決められない。

## 1. 問いがないまま始める

- 悪い例: 「顧客: 電動化が進む。競合: 大手 3 社。自社: 技術力がある」
- 良い例: 「問い: 3 つの成長市場のうち、自社が競合より上回れるのはどこか（論点ツリーの Q-xxx の下）」と書いてから始める

「3C やって」とだけ言われたら、何を決めるための 3C かを聞き返す。

## 2. 自社から始める

自社の得意なことから書くと、それが顧客の基準に見えてくる（プロダクトアウト）。

- 悪い例: 「強みは量産立ち上げの速さ。だから顧客は速さで選ぶ」
- 良い例: 「顧客の基準（仮説）: 量産立ち上げの速さ。確かめる: 完成車メーカーの購買担当に、採用の決め手を聞く」。そのうえで自社の行を書く

## 3. 三つの C を別々の行で書く

顧客は「ニーズ」、競合は「売上と利益率」、自社は「強み」と、違う軸で書くと、比べられない。KSF も導けない。

- 良い例: 顧客の購買基準を行にして、競合と自社をその同じ行で書く

## 4. 事実と解釈を混ぜる

- 悪い例: 「顧客は価格より品質を重視している」（出典なし）
- 良い例: 事実の列に「市場は年 15% [F-xxx]」、解釈・仮説の列に「品質重視（仮説。インタビューで確かめる）」

アウトサイドインでは、顧客の購買基準はすべて仮説である。それを事実の列に書かない。

## 5. 強みがあれば勝てると考える

強みとニーズが合っても、競合がもっとうまく満たしていれば勝てない。

- 悪い例: 「自社は技術営業が強い → 勝てる」
- 良い例: 「KSF の上で一番強い競合と比べて、上回る / 並ぶ / 下回る / —。根拠は ID か 仮説」

## 6. 競合を同業だけにする

顧客の内製、別の技術、隣の業界からの参入を見落とす。代替品と新規参入者を少なくとも 1 行は検討する。

## 7. もっともらしく埋める

財務の比較表から、競合の製品ごとの強さは読めないことが多い。読めないセルは — のまま残す。埋めたくなったら、それは仮説の列に書き、確かめる方法を添える。

## 8. 顧客を広く取りすぎる

「自動車業界」を一つの顧客にすると、内燃機関向けと EV 向けの違いが消える。顧客の使い方で 2〜4 個に分ける。

## 9. 一度作って終わる

3C は一時点の写真である。KSF は競争の構造が変わると変わる。インタビューで仮説が確かめられたら、差分で更新する（インサイドアウト）。

## 10. 点数で順位を付ける

根拠のない重みと点数で「総合点」を出さない。人がセグメントを選べるよう、KSF の上での位置とギャップを並べるところまでにする。
