# value-chain

## 概要

1 つの事業（セグメント）と、答えたい問い、比べる競合を渡すと、その事業のバリューチェーンを返す。活動は Porter の一般形の 9 つの箱ではなく、業界に合わせて言い換える。活動ごとに、会社がやっていること、コストや資産のかかり方の根拠（台帳の ID か —）、コスト要因と差別化要因、競合との違い、活動どうしの連結を書く。どれが事実で、どれが会社の主張で、どれが仮説かを 1 行ずつ分ける。どの活動を優位の源と見なすかは人が決める。

## このフレームワークについて

バリューチェーンは、Michael Porter が『競争優位の戦略』（Competitive Advantage、1985 年）で示した枠組みである。事業を、購買物流・製造・出荷物流・販売・サービスの主活動と、全般管理・人事・技術開発・調達の支援活動に分け、その差がマージンになると考える。McKinsey は 1980 年に、ほぼ同じ考え方を「ビジネスシステム」として示していた。

答える問いは 2 つである。

- どの活動（と、活動どうしのつながり）が、コストか差別化の優位を生んでいるか
- 価値と資本は、どの活動にあるか

次のものではない。

- 会社全体の強み・弱みの一覧ではない（それは [swot](../swot/README.md)）。事業ごとに 1 本描く
- 9 つの箱を埋める作業ではない。業界に合わない箱は言い換えるか、まとめる
- 活動ごとの原価を外から当てる道具ではない。外から分からない値は — で残す
- シナジーの金額を出す道具ではない（金額は [business-case-model](../business-case-model/README.md)）

## 利用メリット

- 経営者の言う強みがどの活動とどの連結の話かを特定し、裏付けがあるかを 1 枚で見られる
- 会社の主張と事実と仮説が分かれているので、下流で主張が事実として扱われない
- 外から分かる数字と分からない数字が分かれ、受注後に社内で取るデータの一覧がそのまま残る
- make / buy / partner、統合シナジー、カーブアウトの議論で「どの活動の話か」がそろう

## 利用シーン

- 売上成長（お題A）: 強みがどの活動にあり、どの打ち手がその強みを生かせるかを見たいとき
- 資本効率（お題B）: 資本コストを下回る事業で、コストや資産がどの活動にかかっているかを見たいとき
- M&A とポートフォリオ（お題D）: 買収相手と重なる活動と、ノンコア事業が本体と共有している活動を見たいとき

依頼の例: 「バリューチェーンで見て」「どこで稼いでるか分解して」「どの機能が強み？」「内製と外注、どこを切り分ける？」「買収したらどこが重なる？」「ノンコアを切り出すと何が残る？」

## 使い方

[financial-analysis](../financial-analysis/README.md) と [competitor-benchmark](../competitor-benchmark/README.md) の後に使う。経営者の言う強みは [leadership-lens](../leadership-lens/README.md) から取る。結果は [option-longlist](../option-longlist/README.md)（打ち手の材料、自前・提携・買収の列）、[capital-capacity](../capital-capacity/README.md)（設備がどの活動にあるか、切り出しの売却資金）、[business-case-model](../business-case-model/README.md)（シナジーとディスシナジーの金額）に渡す。顧客と競合から見た立ち位置は [three-c](../three-c/README.md)、供給業者と買い手の力は [five-forces](../five-forces/README.md) で見る。

1. 描く事業を 1 つ、答える問い（コストの位置 / 差別化の源 / make・buy・partner / 統合シナジー / カーブアウト）、比べる競合を決める。
2. スキルが、一般形の 9 つの箱を業界に合わせて言い換え、その理由を書く。
3. スキルが、活動ごとに会社がやっていること、強度の根拠（台帳の ID か —）、コスト要因と差別化要因、競合との違いを書き、事実・会社の主張・仮説のラベルを付ける。
4. スキルが、活動どうしの連結と、供給業者・顧客のチェーンへのつながり（価値システム）を描く。
5. 問いに合わせた節（make / buy / partner、統合シナジー、カーブアウト）を足す。
6. 候補を並べて止まる。人が決めたら decisions.md に D-xxx で残す。

## 人が決めること

- どの活動・連結を優位の源と見なすか（会社の主張のままのものを含めるか）
- どの活動を make / buy / partner の候補にするか
- お題D では、どの重なりをシナジーと見なすか、どの共有活動を切り出しの障害と見なすか
- インサイドアウトで取るデータを、受注後に依頼するか

単独度は ○（結果をレビューに出す前提）。スキルは表と候補をそろえて止まる。

## よく外す点

- 一般形の 9 つの箱を、どの会社にも当てはまる文で埋める
- 会社全体で 1 本のチェーンを描き、事業ごとの違いを消す
- 活動ごとの原価の割合を、外から推定で埋める
- 経営者の言う強みを、そのまま事実として書く
- 強みを単独の活動の「得意」で書き、活動どうしの連結を書かない
- カーブアウトで、本体と共有している支援活動（調達契約、IT、経理、拠点）を見落とす

詳しくは [references/pitfalls.md](references/pitfalls.md)。出典は [references/sources.md](references/sources.md)。

## 具体例

B2B の精密部品メーカー（売上 2,000 億円、自動車・産業機械・電子の 3 事業）の自動車部品事業を描いた例（抜粋。値と ID は説明用）。社長は「強みは量産立ち上げの速さと、顧客の設計段階から入り込む技術営業」と述べている。

| 活動 | 会社がやっていること | 強度の根拠 | 差別化要因 | ラベル |
|------|------------------|----------|----------|-------|
| 受注前の技術営業・設計参画 | 顧客の設計段階から入り、部品の仕様を提案する | —（活動別の人員・費用は非開示。インサイドアウト） | 採用されるまでの速さ、設計への提案 | 会社の主張（統合報告書のトップメッセージ） |
| 試作・量産立ち上げ | 試作から量産ラインの立ち上げまで | —（立ち上げ期間は非開示） | 立ち上げの速さ | 会社の主張。前の中計で EV 向け部品の立ち上がりが 1 年遅れた事実と食い違う |
| 量産 | 国内外の工場で量産 | 設備投資 ÷ 売上 5.5% [F-280]（連結。活動別は不明） | 品質、コスト | 事実（数字）/ 要因は仮説 |

連結（仮説）: 設計参画で仕様を一緒に決める → 立ち上げで作り方の手戻りが少ない → 立ち上げが速い。確かめ方は、試作から量産までの期間と設計変更の回数（受注後に社内データで取る）。

人に返す判断: 「設計参画 → 量産立ち上げ」の連結を優位の源と見なすか（いまは会社の主張のみ）。判断待ち。
