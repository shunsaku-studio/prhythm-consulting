# workplan

## 概要

優先順位の決まった論点ツリー（01-issue-tree.md）と案件の期間を渡すと、論点と仮説ごとに「どの分析で、どのデータで、どのスキルで、誰が、いつまでに、どのファイルに」を並べた作業計画を返す。人が判断するゲートと、先輩質問タイム 3 回の日程も計画に入れる。

## 利用メリット

- 仮説 1 つに分析 1 つが対応し、答えに効かない作業が消える。
- はしごの順（目標 → 論点 → 事実 → ギャップ → 打ち手 → 資本 …）に依存関係を並べるので、入力より先に締め切りが来ない。
- 質問タイムをゲートの前に置くので、最後にまとめて直す事態を避けられる。

## 利用シーン

- 検証する仮説の優先順位が決まった直後（お題A の 2〜3 日目）
- ゲートで下の段に戻ることになり、計画を引き直すとき

依頼の例: 「ワークプラン作って」「誰がいつまでに何やるか整理して」「質問タイムいつ入れる？」

## 使い方

**いつ使うか:** issue-tree で優先順位が決まった後に入る。計画の各行が、以降のスキルの呼び出しになる。

1. 優先順位の決まった論点ツリー、案件の期間と提案日、チームの顔ぶれを渡す。
2. スキルが仮説ごとに分析、データ、スキル、出力ファイルを置く。
3. スキルがはしごの順に並べ、依存関係から締め切りの案を置く。
4. スキルがゲートと質問タイム 3 回（目標の解釈の前、追う打ち手を選ぶ前、最終メッセージの前）を日程に入れる。
5. スキルは止まり、担当と締め切りをマネージャーに決めてもらう。

## 人が決めること

- 担当と締め切り（スキルは案を出すだけ）
- ゲートと質問タイムの日程
- 期間内に終わらない分析を落とすか

## よく外す点

- 仮説に結び付かない分析が計画に入っている
- 入力ができる前に、後の段の締め切りを置いている
- 質問タイムをゲートの後や、提案の前日に置いている
- アウトサイドインなのに、社内データが要る分析を計画している

詳しくは [references/pitfalls.md](references/pitfalls.md)。
